# 手势语音识别版1.1.2 使用说明（当前版本）

## 一、打开与编译

解压下载包，打开 GestureVoice/GestureVoice.ino；同目录全部.h文件需保留。
主控为经典ESP32-WROOM-32E-8N，Arduino选择ESP32 Dev Module，Flash 8MB、PSRAM Disabled，分区8M with spiffs (3MB APP/1.5MB SPIFFS)。
依赖ESP32 Arduino 3.2.0-cn、U8g2 2.34.22、CheezsEMG 1.0.2、ArduinoJson 7.2.0。
Compile.ps1仅编译，不上传、不打开串口。下载包只提供源码，不含预编译固件。

## 二、手机配置

没有保存网络配置时连接设备开放热点ESP32，打开http://192.168.4.1，填写Wi-Fi名称、密码及百炼API密钥。
保存后设备重启并主动连接Wi-Fi；配置在断电后保留。GPIO33按钮按住约1秒清配置并重启。
PrivateConfig.h是空模板，请勿将真实密钥提交公开仓库。私人网页调试服务器默认关闭。

## 三、当前六种操作

上翘保持：持续上翻字母或候选，回位停止。
下压保持：持续下翻字母或候选，回位停止。
顺时针画圈：加入单引号拼音分隔符。
逆时针画圈：回退／删除。
右侧翻：确认当前字母；在候选界面确认句子并播报。
大致自然位握拳约1秒：提交拼音请求中文联想。

五种手腕动作只使用MPU6050，不依赖肌电佩戴；握拳需要正常佩戴肌电。
当前模型已固化，不需要c/u/d/r/l/g六步校准。上电先在自然位放松，c可重新记录自然位。
单通道肌电不能区分具体哪两根手指接触。

## 四、连续上下翻

首次直接进入连翻需要沿上下轴偏转至少40度并保持300毫秒；模型已经确认上下翻且仍保持至少30度时可以接续连翻。
字母正常重复间隔300毫秒，候选450毫秒。小幅回落不再按“比最高点回落10度”直接结束。
轻微抖动时先暂停发出操作，稳定120毫秒后恢复普通重复间隔。
回到24度以内、反向、明显转动、轴向不符或数据中断仍停止；此参数仍需实物佩戴验证，不保证零误触。
画圈和右侧翻仍由200帧模型窗口识别，速度不同于连续选择。

## 五、当前接线

主控：经典 ESP32-WROOM-32E，8MB Flash、无PSRAM。

| 模块 | 接线 |
|---|---|
| MPU6050 和 OLED | SDA GPIO21，SCL GPIO22，共地；按模块规格供电，I²C逻辑使用3.3V |
| 肌电模拟信号 S | GPIO34（ADC1，可与Wi-Fi同时使用） |
| 肌电佩戴信号 L | GPIO2 |
| 肌电指示灯 | GPIO5、18、19；保留原滤波包络6/9/12三级显示 |
| MAX98357 | BCLK GPIO26，LRC/WS GPIO25，DIN GPIO27；喇叭接SPK+/SPK− |
| HC-04 UART2 | ESP32 RX GPIO16接模块TX，ESP32 TX GPIO17接模块RX，57600 |
| 预留 UART1 | ESP32 RX GPIO4、TX GPIO13，9600，默认不启用每秒发送测试 |
| 配置重置按钮 | GPIO33接按钮，另一端GND；内部上拉，按住约1秒清配置并重启 |
| USB调试 | 115200 |

芯片输入不接受5V逻辑；具体模块电源端电压按模块规格确定。GPIO2为启动相关引脚，启动状态还需结合实物电路检查。


## 六、联想与调试

拼音示例w'x's'j，握拳请求中文候选；上下选择，右侧翻确认播报。
联想现使用qwen3.7-flash，关闭思考模式；qwen-turbo已下线。API账号权限、额度与实际返回效果需验证。
USB串口115200：p查看版本和状态，t切换诊断，h查看帮助，c重新记录自然位。
网络和播报期间丢弃动作，结束后先放松再操作。
联想失败请查看HTTP状态及服务错误码，不要仅根据429就认定余额不足或请求太频繁。

## 七、验证与限制

当前公开源码已编译成功（ESP32 8MB/无PSRAM），程序55%、全局变量25%。最新容错修改后未重跑完整回归；实物、云端调用和新版误触效果待验证。
离线验证入口python tests/run_all_tests.py；环境与可选私人数据见docs/VALIDATION.md。

# 手势语音识别版1.1使用说明

## 一、项目功能

本工程将肌电与手腕姿态识别接入拼音选字、云端联想和语音播报。

当前保留六种本地手势：

- 上翘：上翻字母或候选
- 下压：下翻字母或候选
- 一侧翻掌：拼音分隔符
- 另一侧翻掌：退格或返回
- 自然位短握后松开：确认
- 自然位持续握约1.5秒：请求联想

本系统不识别具体哪两根手指接触。单通道肌电主要反映前臂肌肉的发力、放松和波动，手腕方向由MPU6050判断。

## 二、工程位置

Arduino IDE打开：

```text
GestureVoice\GestureVoice.ino
```

同目录头文件必须一起保留：

```text
GestureCore.h
GestureSensor.h
InputRouter.h
PrivateConfig.h
```

## 三、硬件接线

| 模块 | 引脚 | ESP32 |
|---|---|---|
| 肌电S模拟信号 | S | GPIO34（ADC1） |
| 肌电佩戴检测 | L | GPIO2 |
| 肌电LED | 三颗灯 | GPIO5、GPIO18、GPIO19 |
| MPU6050 | SDA/SCL | GPIO21/GPIO22 |
| OLED | SDA/SCL | GPIO21/GPIO22，与MPU6050共用I2C |
| MAX98357 | BCLK/LRC/DIN | GPIO26/GPIO25/GPIO27 |
| HC-04 Serial2 | TX/RX | GPIO16（RX2）/GPIO17（TX2），57600 |
| 额外Serial1 | RX/TX | GPIO4/GPIO13，9600，仅预留 |
| 配置重置按钮 | 按钮一端 | GPIO33，另一端接GND，内部上拉 |
| USB调试串口 | USB | Serial，115200 |

肌电S必须接GPIO34，不要接GPIO4。GPIO34使用ADC1，可以在Wi-Fi开启时进行模拟采样。所有模块必须共地，进入ESP32的串口信号必须确认是3.3V逻辑电平。

MAX98357的SPK+和SPK-接喇叭正负端，SPK-不要接ESP32 GND。

## 四、Wi-Fi和API手机配置

设备没有保存配置时，会创建无密码配置热点：

```text
热点名称：ESP32
配置地址：http://192.168.4.1
```

OLED显示：

```text
等待Wi-Fi配置
热点: ESP32
手机连热点后打开:
192.168.4.1
```

手机连接热点后填写：

- 目标Wi-Fi名称
- 目标Wi-Fi密码
- 云服务API密钥

点击保存后，配置保存到ESP32内部Preferences存储，设备自动重启并连接目标Wi-Fi。普通断电重启不会丢失配置。

`PrivateConfig.h`只保留空模板，不应填写并提交真实密码或API密钥。

## 五、重置按钮

GPIO33按钮按住约1秒后会：

- 清除保存的Wi-Fi名称和密码
- 清除API密钥
- 清除已保存手势校准
- 断开Wi-Fi并关闭配置热点
- 自动重启
- 重新进入手机配置流程

## 六、六步手势校准

首次使用或更换佩戴位置后，依次执行：

```text
c → u → d → r → l → g
```

每一步需要等待准备提示并保持约2秒：

- `c`：自然位放松
- `u`：上翘
- `d`：下压
- `r`：一侧翻掌
- `l`：另一侧翻掌
- `g`：回自然位后握拳

完成`g`后松开，回到自然位并等待“可以操作”。程序保存自然位、四个方向姿态模板、握拳阈值和放松阈值。以后断电重启会自动加载，不需要每次重新校准。

校准数据保存命名空间：

```text
gesture-cal
```

更换用户、移动电极或改变自然手位后，应重新校准。校准失败时只重发当前步骤；发送`c`可重新开始。

## 七、识别容错

当前版本包含：

- 抬腕时肌电升高会取消旧握拳判断，但保留方向识别机会。
- 短暂接触抖动只暂停输入，不立即永久锁定。
- 持续脱落或接触异常会禁止操作。
- 接触恢复后需要稳定，并回自然位放松。
- 移动、接触暂停和回位会打断对应计时，避免拼接不连续动作。
- MPU读取失败、姿态无效、肌电异常和采样过期不会被接触暂停掩盖。
- 握拳力度存在波动时，短暂低于松开阈值不会立即结束握拳；当前松开确认时间为约400毫秒。

短握和长握仍需要通过实际佩戴测试调整。当前程序保留原有状态机，不把一次模型或阈值判断直接当作最终动作。

## 八、串口和网页调试

### USB串口

USB串口用于启动信息、诊断和校准，波特率115200。可以发送：

```text
c/u/d/r/l/g：校准
w/s/f/b/x/空格：辅助输入
p：完整诊断
t：姿态诊断开关
h：帮助
```

### Serial2与HC-04

```text
HC-04 TX → GPIO16
HC-04 RX → GPIO17
波特率：57600
```

当前Serial2连接的是HC-04，不是脑电模块。脑电解析示例没有作为当前硬件功能使用。

### Serial1

```text
外部模块TX → GPIO4
外部模块RX → GPIO13
波特率：9600
```

Serial1只初始化预留，当前不自动读取、打印或触发业务。每秒发送`s`的测试代码已经停用。

### 网页远程校准

服务器网页地址：

```text
http://<your-server>:3000/
```

网页可以显示设备状态，并发送`c/u/d/r/l/g`远程校准指令。ESP32主动连接服务器，不需要服务器直接访问ESP32。

网页调试通信只用于未完成校准时。校准开始后暂停HTTP请求，校准完成后停止网页调试通信，避免网络请求、阻塞等待和重复打印影响正常肌电、MPU和手势识别。

服务器服务文件位于服务器的：

```text
<server-project>/server.py
```

## 九、云端联想和语音播报

输入流程：

```text
手势/串口 → 拼音字母 → 分隔字 → 确认 → 云端候选 → 选择句子 → 云端语音 → MAX98357播报
```

云端联想和语音合成需要Wi-Fi与API密钥。本地校准、本地翻字母和本地选字不依赖云端。

联想、语音合成、下载和播放期间会进入忙态：

- 暂停手势和串口输入
- 不缓存、不回放忙态期间的动作
- 结束后清除旧姿态缓存
- 必须回自然位放松后继续

## 十二、当前边界

- 单通道肌电不能可靠区分具体哪两根手指接触。
- 当前识别目标是肌电握拳/放松与MPU手腕姿态的融合。
- 云端大模型和语音服务需要网络、API密钥和账户额度。
- 网页调试服务为实验辅助工具，HTTP接口尚未配置完整身份认证，不应直接当作安全生产服务。
- 真实佩戴下的动作准确率、短握长握稳定性、长期电极接触和电源抗干扰仍需实物测试。
